# Incident memo — 2026-10-12 demo run that wrote real state

One round-6 driver (`handoff/s45_politeness_lines.py`, the §4.5 politeness/receipt
driver) was first run **before** it redirected `localdata/`, so instead of a scratch
directory it wrote the repository's real state: two tracked files were modified and
one untracked ledger was created. The files were restored, the driver was fixed, and
the run was repeated clean. This memo answers the three questions the reviewer asked
about that run: the outbound request count, the two files' pre-run status, and the
reusable scratch redirect.

Re-measure any line here:

```
PYTHONPATH=src .venv/bin/python handoff/incident_outbound_probe.py      # (a)
git show HEAD:localdata/betexplorer_capture_2026-10-12.json | sha256sum # (b)
PYTHONPATH=src .venv/bin/python handoff/scratch_localdata.py           # (c)
```

## (a) The bad run's outbound request count: **0**

The bad run's own section-3 receipt reads:

```json
{
  "be_429": 0,
  "be_cached": 1,
  "be_cooling_down": false,
  "be_rows_rejected": 0,
  "be_rows_rejected_reasons": {},
  "market_budget_stop": false,
  "market_requests": 0,
  "requests": 0
}
```

Those zeros are **genuine, not masked**, and the answer is 0 rather than "unknown":

1. **The receipt's window cannot hide a dial.** `scripts/capture_betexplorer.capture()`
   calls `source.reset_fetch_count()` at `scripts/capture_betexplorer.py:201` (the line
   immediately *before* the fixture loop, which starts at line 203) and reads
   `source.request_stats()` at line 219 at the *end* of the same call. One window:
   reset → loop → stats. `edgefactory.sources.betexplorer_odds._fetch` increments
   `_request_count` at line 185, immediately before `urlopen`, and `reset_fetch_count`
   (line 1402) is the only reset — nothing after the loop resets. A dial inside that
   window would have printed as `requests >= 1`.
2. **What the run actually did.** Two call sites could dial:
   * `_run_pick(PICK, calls=calls)` (the tests' helper, driver line 70) runs the real
     `betexplorer_odds_rows_for_pick`, but with `be._fetch` patched by the helper's
     canned `_transport` — 9 fetch calls were *served from the stub*; the real counter
     never ran.
   * the capture itself, `capture("2026-10-12", max_fixtures=1)` — one fixture, answered
     from the same-day cache (`be_cached: 1`), the one path that returns before `_fetch`
     is reached.
3. **Measured, with the network blocked and counted.**
   `handoff/incident_outbound_probe.py` re-runs exactly those two sections with
   `urllib.request.urlopen` and `betexplorer_match_snapshot.fetch_page` replaced by
   counting blockers (so a dial would be *recorded*, and cannot leave the sandbox
   either way). Result, in `handoff/incident_2026-10-12_outbound_count.txt`:

   * `urlopen attempts during the probe      : 0`
   * `match_snapshot.fetch_page calls        : 0`
   * the re-run's receipt is **byte-identical** to the bad run's receipt above.

**Scope of the counter (stated so the number is not over-read):** `requests` counts
this module's `_fetch` attempts only. `betexplorer_match_snapshot.fetch_page` is a
second dial site with no counter, and it is not on the capture path (the capture
imports `parse_match_page_blocks` only). Any `fetch_page` traffic in that run would be
invisible to `requests` — the probe's blocking wrapper is what rules it out for this
run's code path.

**Blast radius had it dialed (bounds, not a count):** `_MAX_FETCHES_PER_RUN: int = 12`
bounds any one run's fetch attempts, and every market request passes
`min_interval=_MARKET_INTERVAL = 5.1`, so *n* dials cost ≥ (n−1) × 5.1 s. The run's
damage was write-side only: one untracked ledger plus two tracked files (below).

## (c) The reusable scratch redirect: `handoff/scratch_localdata.py`

One helper, used by every chain driver. It is not an env-var one-liner because the
shipped code resolves localdata twice, at two different times:

* `edgefactory.sources.*` and `edgefactory.source_health` read `EDGE_FACTORY_LOCALDATA`
  **at import time** — so the variable must be set *before* those modules import;
* `warehouse.LOCALDATA` and the module-level constants derived from it (e.g.
  `auto_tickets.STATE_FILE`, `picks_today.AUDIT_ROLLING_PATH`,
  `scripts.capture_betexplorer.LOCALDATA`) are hard `ROOT / "localdata"` paths bound at
  import — an env var alone does nothing for them.

`guard_localdata()` therefore (1) sets `EDGE_FACTORY_LOCALDATA` first, (2) imports the
chain's candidate modules, (3) re-points every module-level `pathlib.Path` attribute of
any already-imported `edgefactory.*` / `scripts.*` module that lives under
`localdata/` into the scratch dir (preserving the relative sub-path), and (4) on
interpreter exit restores every attribute and prints
`git status --porcelain -- localdata/` — on **stderr**, because several drivers' stdout
is a recorded artifact that must not change by a byte.

Two modes: `mode="mirror"` (default) copies the repo's `localdata/` into the scratch
first, so a driver reads what it would have read and writes nothing real;
`mode="scratch"` starts empty. `scratch_localdata()` is the scoped context-manager
form; `strict=True` exits non-zero if the exit check finds a real write.

Coverage — every driver in this chain now calls it as its first act (12 drivers), and
the helper's own selftest writes through each module's own path helper and asserts
nothing lands in the repo:

| driver | writes | guard run |
|---|---|---|
| `handoff/s45_politeness_lines.py` | 2 paths | stdout identical to the committed artifact (3 timing lines differ) |
| `handoff/flag_gate_2026-10-12/prove_flag_gate.py` | 5 paths | imports and engages the guard |
| `handoff/round5_form_h2h_2026-10-12/intel_report.py` | 4 paths | ran clean, printed the same 409-record join |
| `handoff/round5_form_h2h_2026-10-12/a_census.py` | 1 path | exit 0, localdata empty |
| `handoff/round5_form_h2h_2026-10-12/s44_excerpt_repro.py` | 1 path | exit 0, localdata empty |
| `handoff/n1_legacy_leg_proof.py`, `handoff/n1_persisted_keys.py`, `handoff/round5_form_h2h_2026-10-12/{w1_probe,w3_identity_census,w4_probe,a_identity_checks}.py`, `handoff/live_2026-10-12/verify_live_pages.py` | 0 | all exit 0, localdata empty |

`PYTHONPATH=src .venv/bin/python handoff/scratch_localdata.py` → selftest PASS: each of
`betexplorer_odds`, `capture_betexplorer`, `auto_tickets.state_path()` and
`picks_today.LOCALDATA` resolves into the scratch dir, writes land there, and the
repo's `localdata/` is untouched.
