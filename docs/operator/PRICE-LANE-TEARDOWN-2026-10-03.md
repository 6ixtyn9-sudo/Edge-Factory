# Price-lane teardown — 2026-10-03

**Scope.** This is an evidence report for the production state persisted in
`960360c` (the state commit generated by Actions run `37104877841`), compared
with the repair work visible on `arena/01a100ac-edge-factory`. It distinguishes
what the committed artifacts prove from what cannot be recovered because the
hosted Actions logs/artifact payload were unavailable in this environment.

## Bottom line

The 2026-10-03 run did **not** have a functioning, integrated multi-source
price lane.

It had a real The Odds API capture, but selection could not consume it:

1. `scripts/daily.py` ran `picks_today.py` before
   `capture_theodds_snapshot()` in the official, intraday, and forecast paths.
2. `capture_theodds_snapshot()` and `capture_theodds.py` described that data
   as CLV/audit-only.
3. `picks_today.py`'s donor loop did not load `theoddsapi`; it only loaded
   Boggio, Bet Better, SharpAPI, BetMiner, and PinnAPI shadow ledgers.
4. The old ticket nevertheless printed two legs whose disclosure says
   **“unregistered source — not a price donor.”**

So the printed `ACCA #1` was not proof that two executable prices had been
found, and it was unsafe that it was printable at all. The state contains no
second eligible two-leg pair, which is why it did not print two accas. A large
prediction slate is not a large executable-price slate.

## Direct artifact checks

### The actual printed ticket

`localdata/auto_tickets_2026-10-03.txt` has 23 lines and exactly one ticket:

* `Sri Lanka vs Djibouti HOME @ 2.60`
* `Piteå W vs Norrköping W HOME @ 2.07`

Both are explicitly annotated `price: unregistered source — not a price donor`.
There is no `[ACCA #2]`. The same report says the selection ladder had only
14 CAUTION candidates after its demotion and cap; the broad candidate count
is therefore not the ticket pool count.

The old behavior was contradictory: the disclosure correctly admitted that
both prices were not registered donors, while the ticket writer still used
them. The imported fail-closed gate now refuses an unknown/disabled price
provenance in the execution-safe lane; regression coverage is in
`tests/test_registered_price_gate.py`.

### The Odds API was not absent

`localdata/theoddsapi_odds_2026-10.csv.gz` is a raw, date-stamped provider
receipt. It contains **404 rows dated 2026-10-03**, covering six fixtures.
With a deliberately later audit cutoff of `2026-10-03T08:00:00Z`, the shared
matcher now produces these six exact fixture/market/selection joins:

| pick fixture / selection | book | decimal | capture timestamp UTC | prior join state |
|---|---:|---:|---|---|
| Albacete — Eibar / away | Betfair | 2.58 | 2026-10-02T22:18:06.649596+00:00 | name alias missing |
| Grimsby — Shrewsbury / home | Matchbook | 1.71 | 2026-10-02T22:18:06.847490+00:00 | name alias missing |
| Cuiabá — Ponte Preta / home | Matchbook | 1.19 | 2026-10-02T22:18:07.299780+00:00 | already exact but unwired |
| Iceland — Bulgaria / home | Betfair | 1.48 | 2026-10-02T22:18:07.634185+00:00 | already exact but unwired |

| Salford City — Fleetwood Town / home | Betfair | 1.68 | 2026-10-02T22:18:06.966034+00:00 | already exact but unwired |

This is evidence of feed and join capability, **not** permission to rewrite
the original card. The official-run receipt gives
`run_as_of = 2026-10-03T00:00:54+02:00` (22:00:54Z on Oct 2). All six rows
above were captured later. The original card therefore had **zero** of these
quotes available at its own selection instant. The repaired loader rejects a
row after the build cutoff, a missing timezone-bearing capture time, and a
row older than 24 hours; it cannot retrospectively price a ticket.

The old `theoddsapi_attempts_2026-10-03.json` is not a row receipt. It records
attempt timing and has combinations such as a `first_at` plus later `fail_at`.
It must not be used to infer zero source rows or zero joined prices; the
compressed CSV is the evidence for those questions.

### Two joins were identity, not fuzzy-matching, failures

The raw provider has `SD Eibar` where the candidate ledger has `Eibar`, and
`Grimsby Town` where it has `Grimsby`. Before this change neither local odds
alias table contained those terms. The repair adds only these canonical,
one-way mappings:

* `Eibar → SD Eibar`
* `Grimsby Town → Grimsby`

`tests/test_theoddsapi_integration.py` creates a gzipped provider receipt and
proves both fixture joins are `exact`, not time-only or fuzzy joins. It also
proves a post-build, timestamp-less, and stale record is withheld. That test
is intentionally hermetic; no live credential or live provider response is
needed to validate the identity rule.

### Other source artifacts do not establish executable fallback prices

* The committed `zulubet.csv.gz`, `forebet.csv.gz`, and `statarea.csv.gz`
  contain no 2026-10-03/04 source rows. The latest committed BetExplorer
  archive is June. They cannot substantiate a current-price fallback claim.
* `OddspAPI` capture/probe code is not called by `daily.py` or the workflow.
  A registry entry is capability metadata, not proof that the scheduled run
  fetched or consumed it.
* SportyTrader is present as a shadow/corroboration candidate, not a donor in
  the active donor-bundle loop. It must not be described as an active price
  source unless its own receipt is present and its role is explicitly enabled.
* Before this repair `.gitignore` ignored every `localdata/*` source-health
  and dated shadow receipt. The workflow's `git add -A localdata/` therefore
  could not persist the very health receipt intended to prove source activity.

## Code changes and the proof each one carries

### 1. Fail closed on price provenance

Cherry-picked from the comparison branch:

* `e04de3d` — canonical donor odds and join health
  (original `d20a966`)
* `36fa250` — unregistered execution prices fail closed
  (original `cb2ac123`)
* `2c4dbc6` — BetMiner and SharpAPI adapter-contract repair
  (original `8b477da`)

This imports the reviewed repair branch's source normalization, source role,
contract, and execution-provenance tests without importing generated run
state. `tests/test_registered_price_gate.py` proves unknown and disabled
sources cannot become execution-safe printable legs. Fair-price staking is
opt-in rather than an accidental default.

### 2. Make named-book provenance deterministic

`price_sources.rank_candidates()` now orders a healthy exact executable
named-book quote ahead of freshness. Previously freshness was evaluated first
and each candidate computed “now” separately; a microsecond timing difference
could make a fair/aggregate donor win over a named-book quote. The prior
failing regression `test_a_healthy_named_book_outranks_a_fair_price_donor`
now passes, and the comparator documentation names the policy.

### 3. Connect The Odds API without time travel

`picks_today.py` now reads the persisted monthly The Odds API CSV as a
**cache-only named-book bundle**. It validates each row's own `captured_at`
before it enters the existing canonicalization and source-ranking path:

* row date and source must match;
* `captured_at` must parse with an explicit timezone;
* it must be at or before the current build's `as_of` time;
* it must be at most 24 hours old;
* it must retain a named bookmaker.

The bundle participates in price selection and the complete price board.
A The Odds API quote is labeled `NAMED_BOOKMAKER_PRICE`, not
`BZZOIRO_PRIMARY`; the latter label remains only for historical Bzzoiro rows.
The test proves the new disclosure names TheOddsAPI and Betfair rather than
misrepresenting the source.

The capture still follows the pick build because `capture_theodds.py --auto`
derives its fixture list from that frozen shortlist. This is deliberate:
the capture is available to a **later** run only. It cannot rewrite the card
that triggered the capture. Both capture docstrings now state that limitation
rather than calling the source universally audit-only.

### 4. Persist an auditable health receipt

`.gitignore` now permits compact `source_health_20*.json` and
`source_health_state.json` receipts while leaving raw shadow ledgers ignored.
The workflow already stages `localdata/`, so a future receipt is commit-able.
The daily source-health contract now records distinct The Odds API counts:

* `oa_raw`: matching-date provider records observed;
* `oa_usable`: rows that survived timestamp/book validation;
* `oa_matched`: rows that actually joined a pick.

The selection-stage status is explicitly `cache_only`, with
`can_fetch_today = false`; reading a persisted board is no longer reported as
an HTTP fetch. `tests/test_donor_join_health.py` proves the receipt and status
line retain all three counts.

## What was not changed or claimed

* This work does **not** issue a revised 2026-10-03 ticket, recalculate its
  stake, or claim the six later observations existed at the official-run time.
* It does **not** claim that six quote joins would necessarily yield three
  accas. Ticket eligibility also depends on the quality/veto ladder,
  kickoff/freeze controls, corroboration, and stake safeguards.
* It does **not** promote every adapter named in `price_sources.py`. A source
  becomes executable only through a registered role, an enabled contract, a
  persisted time-qualified receipt, and an exact join.
* A broad historical remine is intentionally deferred. The new controls
  improve evidence and price provenance, not historical prediction labels;
  a remine without newly verified source receipts would fabricate a change in
  historical knowledge. Reconsider it only after the persisted health receipts
  show repeated usable/matched rows and a predeclared backtest window.
