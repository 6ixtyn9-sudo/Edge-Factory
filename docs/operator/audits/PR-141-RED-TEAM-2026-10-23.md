## F1 — later board observations can invalidate an earlier eligible decision

**P2, confirmed regression from the additional board input.**

Locations at the reviewed commit:

- `src/edgefactory/enh_pricing.py:553,574-577`: index construction resolves
  schedules using the fixed 09:00 Johannesburg cutoff, not the pick's as-of.
- `src/edgefactory/kickoff_corroboration.py:455-475`: all witnesses before that
  cutoff participate in resolution/conflict checking.
- `src/edgefactory/enh_pricing.py:490-503`: attachment subsequently rejects a
  receipt containing any witness at/after the actual decision.

Synthetic reproduction, using real CSV loading, BE attachment and admission:

1. Independent CSV schedule observed 05:30Z; BE quote captured 06:00Z;
   decision 06:30Z; fixed cutoff 07:00Z; kickoff 20:00Z.
2. Without the board, BTTS-No @2.25 is admitted.
3. Add a cached board observed **06:45Z**, after the decision but before cutoff.
4. If it agrees on 20:00Z, seven BE cells reach the index, but the selected
   receipt contains the future witness and attachment loses the valid price.
5. If it instead says 19:00Z, the earlier loader records
   `conflicting_schedule_witnesses` and admits zero cells.

Both desired-invariance tests pass on pre-PR141 code and fail on merged code.
The underlying cutoff/as-of mismatch predates PR141; consuming the board adds
a new trigger for it, rather than introducing the original time-check design.
This is future-information influence causing a false negative, **not** an
accepted lookahead price. The original test that a future-only board cannot
create a price did not cover poisoning an existing eligible witness.

Repair direction for independent review: bound schedule knowledge by the actual
aware decision before conflict resolution/quote selection. A shared day index
must not let a later observation poison an earlier pick. Do not simply relax the
execution-time check or discard genuine pre-decision conflicts.

## F2 — per-fixture best-book collapse can erase a viable complete acca

**P2, confirmed inherited integration defect; not introduced by PR141.**

Locations:

- `src/edgefactory/enh_pricing.py:589-610`: BE rows collapse to one flagged/best
  quote per `(market, selection)` before insertion into the quote index.
- `scripts/auto_tickets.py`: `enhancement_legs`, `enhancement_pool`, `plan_day`
  subsequently require executable same-book/source complete pairs.

Synthetic reproduction through the actual live leg door and ticket recipe:

| Fixture | Retained common-book offer | Higher disjoint-book offer |
| --- | --- | --- |
| A | Common Book @2.25 | Only First Book @2.50 |
| B | Common Book @2.25 | Only Second Book @2.50 |

Both common-book offers have the same valid schedule, timing, source and
explicit synthetic cohort context as their higher counterparts. With only the
common offers retained, the real recipe produces one two-leg acca. Adding the
higher offers leaves two firing legs at different books and **zero** complete
accas, although the common-book quotes still exist in the input ledger.

The same desired-behaviour assertion fails against pre-PR141 and merged code.
This does not justify relaxing same-book/source pairing. It demonstrates that
single-leg best-price selection is insufficient for complete-ticket competition.

Repair direction: preserve valid per-book variants through the existing quote
index, candidate expansion and complete-ticket competition. Merely inserting
more quotes into the index is insufficient if attachment/event notes still drop
all but one before pairing. Reuse existing machinery; no parallel registry or
new staking/selection model.

## F3 — one corrupt odds archive can disable valid cached-board admission

**P2 availability/robustness finding, inherited; policy-sensitive repair.**

Locations:

- `src/edgefactory/kickoff_corroboration.py:305-317`: CSV archives are opened
  before the board, without a per-file exception boundary.
- Same file `:370`: cached board reading occurs only after all CSV scans finish.
- `src/edgefactory/enh_pricing.py:574,614-615`: the resulting exception silently
  aborts BE accumulation rather than returning already valid witnesses.

Reproduction: a valid BE quote and independent cached board admit BTTS-No
@2.25. Add `oddspapi_odds_2026-09.csv.gz` containing invalid gzip bytes; the
price becomes unavailable. Also reproduced with a valid October CSV witness
present, both on the pre-PR141 baseline and merged code. No malformed archive
rows became prices.

Repair direction for review: isolate and explicitly diagnose input-file failures
so a damaged archive cannot silently disable every BE fixture and prevent board
inspection. Decide conservatively how unavailable potentially relevant schedule
history affects conflict guarantees; **do not blindly ignore corruption and
claim complete corroboration**. The observed failure is confirmed, but whether
a particular damaged input may safely be excluded requires an explicit contract.
