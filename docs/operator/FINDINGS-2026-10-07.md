### Why the guard fires (OBSERVED mechanics)
`_same_club_names` (`auto_tickets.py:1949`) links a pair via `entities.canonical_team`,
`identity.source_team_key`, structural containment, or a single abbreviated token of
length ≥ `_MIN_ABBREVIATION_LEN` (2). Measured on the exact pairs:

| pair | verdict | reason |
|---|---|---|
| `Giravanz K.` ↔ `Giravanz Kitakyushu` | **False** | abbreviated token `k` is 1 char — below the floor by design |
| `Samgurali Tsqaltubo` ↔ `Samgurali Tskhaltubo` | **False** | c/q transliteration is not bridged |
| `Samgurali` ↔ `Samgurali Tsqaltubo` (and the other 3 short/prefix forms) | True | structural containment already links them |

So in each case the *only* failing seam is one spelling pair; everything else on the date
links. `_drop_ambiguous_result_keys` (`auto_tickets.py:2077`) then treats the shared key as
covering two different fixtures: a truncated key is *superseded* (the leg still settles
from a full-width tier; 773 today), a wide key with disagreeing outcomes becomes
*ambiguous-pending* and the leg is left for manual verification (`settlement_ambiguous_pending=0`
in this checkout's re-run — no pending leg touches these two dates today).

### The alias is the wrong fix — measured, not argued
In-memory experiment (patched `util._TEAM_ALIAS_CACHE`, cleared the cached canonicaliser,
reloaded `auto_tickets`; nothing written): the alias flips `_same_club_names` to True and
the ambiguity report disappears. It does **not** change the outcome, because `key_to` is
first-writer-wins (`setdefault`): for 2026-08-01 the shared tier holds `draw`/0-0 while a
wider tier holds `home`/1-0. The alias lowers the guard and leaves the disagreement
standing, so the report would stop naming a real problem. **Do not add it** — to
`Config/entity_overrides.json` (that is the `canonical_team` route the guard reads) or to
`localdata/team_aliases.json` (that only feeds `_alias_variants` in `pick_result`, where it
would change *what settles* by letting a pending leg find a variant key — outside the fence).
