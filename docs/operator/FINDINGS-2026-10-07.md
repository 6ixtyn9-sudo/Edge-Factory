### Why the guard fires (OBSERVED mechanics)
`_same_club_names` (`auto_tickets.py:1949`) links a pair via `entities.canonical_team`,
`identity.source_team_key`, structural containment, or a single abbreviated token of
length ≥ `_MIN_ABBREVIATION_LEN` (2). Measured on the exact pairs:

| pair | verdict | reason |
|---|---|---|
| `Giravanz K.` ↔ `Giravanz Kitakyushu` | **False** | abbreviated token `k` is 1 char — below the floor by design |
| `Samgurali Tsqaltubo` ↔ `Samgurali Tskhaltubo` | **False** | c/q transliteration is not bridged |
| `Samgurali` ↔ `Samgurali Tsqaltubo` (and the other 3 short/prefix forms) | True | structural containment already links them |

So in each case the *only* failing seam is one spelling pair; everything else on the date
links. `_drop_ambiguous_result_keys` (`auto_tickets.py:2077`) then treats the shared key as
covering two different fixtures: a truncated key is *superseded* (the leg still settles
from a full-width tier; 773 today), a wide key with disagreeing outcomes becomes
*ambiguous-pending* and the leg is left for manual verification (`settlement_ambiguous_pending=0`
in this checkout's re-run — no pending leg touches these two dates today).

### The alias is the wrong fix — measured, not argued
In-memory experiment (patched `util._TEAM_ALIAS_CACHE`, cleared the cached canonicaliser,
reloaded `auto_tickets`; nothing written): the alias flips `_same_club_names` to True and
the ambiguity report disappears. It does **not** change the outcome, because `key_to` is
first-writer-wins (`setdefault`): for 2026-08-01 the shared tier holds `draw`/0-0 while a
wider tier holds `home`/1-0. The alias lowers the guard and leaves the disagreement
standing, so the report would stop naming a real problem. **Do not add it** — to
`Config/entity_overrides.json` (that is the `canonical_team` route the guard reads) or to
`localdata/team_aliases.json` (that only feeds `_alias_variants` in `pick_result`, where it
would change *what settles* by letting a pending leg find a variant key — outside the fence).

### 8.7 R2.4 — valid draw-value bar and candidate preregistration

> **R2.4 PRE-REGISTERED DRAW-VALUE BAR (operator-supplied, 2026-10-07; commit this text before running any query).**
>
> Mission: discovery only. Determine whether any draw-selection rule on `consensus3` shows evidence of value. Nothing is adopted; no threshold, gate, floor, cap, quorum, veto, stake, bank, or emission rule moves; no pick is emitted; no registry write.
>
> Data: eligible `consensus3` rows (settled outcome; non-null `fb_p`, `zb_p`, `sa_p`), 2024-01-01 → 2026-06-12. The rule family and its exact predicate are declared **before** the run. Every parameter choice is made on the train slice `date < 2025-06-01` (n=12,007) and frozen; the calibration slice may inform one parameter if stated; a parameter chosen after seeing test results voids the candidate.
>
> Report slice: held-out test `2026-01-01 ≤ date ≤ 2026-06-12` (n=2,935).
>
> Prices: archived (reserved) `pick_odds` only. Rows without a raw archived price are excluded from ROI and counted; the 1.50 fallback is never used for ROI.
>
> A candidate is **reported** (never adopted) only if ALL FOUR clauses pass on the held-out test slice:
>
> 1. **Cell:** n ≥ 100 draw picks.
>
> 2. **Rate:** realised draw hit rate ≥ 29, AND the Wilson 95% lower bound on that rate ≥ the break-even rate `1 / mean archived odds` for the cell.
>
> 3. **Return:** flat-stake archived-price ROI &gt; 0 on the test slice AND &gt; 0 on the calibration slice.
>
> 4. **Stability:** n ≥ 30 with ROI &gt; 0 in each half of the test window (2026-01-01…03-31; 2026-04-01…06-12).
>
> Required output whatever the outcome: the rule predicate verbatim; each clause's cell with n; rule volume per window (picks/day); price distribution; concentration check (share of picks in the top-10 fixtures). "No candidate" is a valid and expected result.
>
> Comparator note (not a clause): the 208-record ml-meta draw history (199 settled, 45W/154L, −30.9% at archive prices) spans **36 model keys and 21 `sources_used` sets**; it is a cross-era aggregate and is **not** a like-for-like benchmark. The clauses above stand on their own.

**Preregistered rule family and predicate (OBSERVED as of this commit; data query not yet run).** Candidate: `consensus3` three-source draw majority. On each eligible settled row, count the stored categorical fields `fb_pick`, `zb_pick`, and `sa_pick` whose stripped, case-folded value is `draw`; select the row as a draw pick iff the count is at least 2. A missing or non-draw source pick contributes no draw vote and is counted in source-pick missingness. No probability threshold, price threshold, model refit, feature search, league filter, or secondary rule is used. The rule has no fitted parameters; therefore train and calibration data choose no parameter. The raw `pick_odds` price is excluded from the selection predicate and used only for the preregistered reporting/economic calculations.

**Calculation conventions fixed before query.** Interpret “hit rate ≥29” as ≥29%. Use the standard two-sided Wilson 95% lower endpoint (`z=1.96`) on the selected settled test rows; break-even is `1 / arithmetic mean of valid raw archived pick_odds` among priced rows in that same cell. Cell/rate n counts selected settled rows including unpriced rows; ROI uses only valid raw-price rows and reports excluded-price n. A flat-stake win returns `pick_odds−1`, a loss `−1`. Volume is selected rows divided by inclusive calendar days in each train, calibration, test, and test-half window. Price distribution reports n, min, p25, median, mean, p75, and max of valid raw `pick_odds`. For the concentration check, rank selected test fixtures by descending mean of `fb_p`/`zb_p`/`sa_p` only for source fields whose corresponding pick voted draw; tie-break by stored date, home, away ascending. Report the top-10 selected-pick share and the top-10 rows' outcomes and priced net P&L. This ranking is descriptive only and cannot change the rule.

### 9.0 Shadow-to-active certification bar — pre-registration

> **SHADOW-TO-ACTIVE CERTIFICATION BAR (operator-supplied, frozen 2026-10-07).**
>
> A candidate era — source set `S`, candidate `model_key` `K`, era cuts `C` derived by the **existing** certification procedure — is certified **ACTIVE** only if ALL clauses pass, evaluated by the deterministic certifier on shadow data only:
>
> 1. **Maturity.** Every source in `S` has ≥90 consecutive days of shadow capture with no gap &gt;7 days; trailing-30-day capture success ≥95% of scheduled attempts; capture timestamp populated on 100% of rows.
>
> 2. **Timing.** For every feature derived from a source in `S`, capture timestamp precedes fixture kickoff on ≥99% of evaluated rows. A failing source is reported as post-kickoff-contaminated and **excluded from `S`** — never silently zeroed.
>
> 3. **Identity.** Marker-aware exact join rate ≥95% on a fixed 200-fixture audit sample; fuzzy is diagnosis only, never a join path.
>
> 4. **Existing gates, unchanged values, on the era's own history.** train n≥340, valid n≥120, recent n≥30 (trailing 30 days), train ROI ≥ −0.10, valid ROI ≥ 0.00, valid Wilson LB ≥ 0.50; paired overlap versus the incumbent era n≥200 on the same fixtures and window.
>
> 5. **No material degradation (paired).** Same fixtures and window, fixture-date cluster bootstrap (10,000 reps, seed 42, two-sided 95%) on the paired difference `candidate − incumbent`: upper bound ≤ **+0.002** Brier and ≤ **+0.005** logloss. Operator-chosen materiality tolerances — fixed now, not revisable by the agent.
>
> 6. **Coverage floor.** Candidate era's eligible scored-fixture count ≥ the incumbent's on the same window; the per-column neutral fallback is enumerated and stated.
>
> 7. **Independence.** Report the new source's pairwise agreement with each existing source on ≥200 common rows; ≥98% agreement is recorded as a **family member** with the vote-weight question named explicitly. Unreported ⇒ clause fails.
>
> 8. **Rollback readiness.** Incumbent era remains selectable; a one-command revert demonstrated (dry run) and recorded **before** activation.
>
> 9. **Sequencing.** At most one activation per 30 days; each era activates once; the incumbent's registry entry and certified cuts are **never mutated** by any activation.
>
> Any clause failing ⇒ no activation, verdict recorded naming the clause. **"Not yet due"** (insufficient data) is a distinct, expected status — not a failure.

**Pre-registration receipt.** This operator-supplied bar is frozen before any source capture, candidate fitting/scoring, or certification evaluation. No clause or gate was changed.
