# Phantom 1x2 price — Viking/Bayern, 2026-10-11 → 10-13

A printed Champions League leg carried `away @ 2.06` for **Viking vs Bayern
Munich**. No book quoted away at 2.06: the real full-time price was **1.088**.
The same snapshot shipped two more real-money legs off the same class of quote
(Galatasaray vs Barcelona away `4.21` vs a real `1.2703`; Arsenal vs Lille home
`2.2` vs a real `1.2358`), and the 2026-10-11 card had already placed one of
them in an accumulator (`localdata/auto_tickets_2026-10-11.txt`, ACCA #1 @2.92:
Benfica 1.22 × Vidar 2.39, true multiple 1.22 × 1.2381 = 1.509, stake 19.3%).

## What was observed

The pick's own `price_board` (archived verbatim in
`localdata/picks_2026-10-13.json`) holds, for a single fixture, a single
bookmaker (`Pinnacle`) and a single capture second
(`2026-10-11T22:14:45Z`), three separate market groups all canonicalised to
`market=1x2`:

| fixture | quotes | implied sum |
|---|---|---|
| Viking vs Bayern Munich | 18.79 / 14.45 / **1.088** | 1.0415 (full-time three-way book) |
| | 16.35 / 1.033 | 1.0293 (two-way) |
| | 1.7813 / **2.06** | 1.0468 (two-way) |

Each pair sums to a plausible single-book margin, so they are **separate
markets**, not stale duplicates of one quote (all rows share one capture
second). The engine's 1x2 index keys on
`(date, home, away, market, selection)` and resolves a same-side tie by
bookmaker priority and then by **largest odds**, so the away pick took 2.06.
Measured against the whole archive: the chosen price equals the maximum
same-side pinnapi quote for **31 of 31** pinnapi-sourced picks.

## Mechanism (code, verified)

1. `scripts/picks_today.py::_odds_bundle_from_rows` keys quotes by canonical
   market + selection. The provider's container name and any line were **not
   part of the key**, so a two-way price could occupy the three-way key.
2. `_prefer_odds_row` resolves the tie by maximum odds — for a heavy favourite
   that is systematically the handicap-shaped quote, because the handicap
   price is always longer than the money-line price.
3. `_price_board_entry` archived the canonical market and dropped `line` /
   `raw_market`, so the archive could not say which container the winning
   quote came from. That is why this document reconstructs the market groups
   from arithmetic instead of from the raw payload: **the raw payload was not
   retained** (the per-date pinnapi ledger is gitignored, and the run's
   artifacts are not retrievable from this workspace). The container-level
   origin is *inferred*; the three coherent groups are *observed*.
4. `src/edgefactory/odds_normalization.py::canonical_market` ignored `line`
   for every non-ou market, so a lined two-way token (`1x2`, `money_line`,
   `h2h`) canonicalised to a line-less 1x2 row.
5. Corroboration was inert for this class (`price_sources.corroborators_are_sufficient`
   is True while `require_corroboration()` is off), and the printed leg was
   stamped `price_push_eligible` / NAMED_BOOKMAKER_PRICE.

## Fix (four layers, so the next occurrence cannot be silent)

| layer | change | where |
|---|---|---|
| provider | a `money_line` container that does not carry all three of home/draw/away is a **named drop** (`money_line_partial_group:<sides>`), never a partial 1x2 book | `src/edgefactory/sources/pinnapi_odds.py::_rows_from_periods` |
| canonicaliser | a 1x2 token carrying any line marker — including a `0` line (Pinnacle renders draw-no-bet as a zero handicap) — is refused as `unsupported_market:<token>_with_line` | `src/edgefactory/odds_normalization.py::canonical_market` |
| join | **coherent-book gate**: per fixture, per `(provider, bookmaker, capture second)`, if a complete trio whose overround lies in `[1.00, 1.20]` exists then only that trio may price 1x2 (the rest is refused as `excluded_not_in_three_way_book`); if no trio exists but a side carries several distinct quotes, the fixture is **withheld** (`withheld_ambiguous_one_x_two`); one quote per side is left untouched | `scripts/picks_today.py::_gate_one_x_two_rows` |
| archive | every board entry now carries `line`, `raw_market`, `raw_selection` and the refusal marker; the gate's counters reach the committed source-health row and the run log; a refused quote can never count as corroboration | `_price_board_entry`, `coherence_observation`, `_stamp_price_board`, `_stamp_price_corroboration` |

Replay of all 514 archived priced 1x2 picks with a board through the real code
path: **408 unchanged**, 11 repriced to their coherent book, 1 withheld
(Atletico Nacional vs Deportivo Pasto, 2026-10-11 — two home quotes and two
away quotes with no complete trio anywhere: every combination is a degenerate
pair, so no price is printed), 91 with no board row for the chosen source, and
3 pre-existing replay artifacts (unchanged with the gate disabled).

## Verification

- `tests/test_pinnapi_odds.py` — a partial `money_line` group is dropped and
  counted; a three-way group beside a two-way group keeps only the three-way.
- `tests/test_odds_normalization.py` — a lined 1x2 token is refused; a `0`
  line counts as a marker; a line-less row and an `ou_2.5` row are unchanged.
- `tests/test_price_coherence_gate.py` — the archived boards (Viking,
  Galatasaray, Arsenal, Atletico) replay to their coherent prices; the withheld
  case stays unpriced; single-quote boards and other markets are untouched;
  refusal markers, counters, health-row passthrough, run-log line and the
  corroboration exclusion are pinned; the 10-13 archive itself is replayed when
  `localdata/` is present.
- `tests/test_theoddsapi_short_league_codes.py` — mapping evidence is now the
  frozen 48-sport catalogue (`tests/data/theoddsapi_sports_2026-10-10.json`);
  live-catalogue drift is asserted as a churn-tolerant property (resolve to a
  mapped key or to None, never to a neighbouring competition). The 2026-10-11
  delisting of Switzerland/Russia/Belgium is simulated deterministically.

## Residuals (honest)

- A book that ships a bare two-sided group and **nothing else** is not caught
  by the join gate: one quote per side is indistinguishable from a complete
  book missing a side. That class needs the provider-side rule (three sides or
  a named drop), which pinnapi now has; other providers' two-way variants
  (Bet Better's bare `Head to Head`) still map to 1x2 and are non-execution
  donors today.
- The tightest-trio rule prefers the *lowest* overround inside the band, which
  in principle could prefer a mixed-market combination over the true trio. The
  band discourages it structurally (a favourite-side phantom pushes the sum
  below 1.00, an underdog-side phantom above the true trio), and on this
  archive it selected the true book in every case — but the guarantee is the
  adapter rule, not the tie-break.
- The container that emitted the extra quotes is inferred. The next capture
  that produces a refusal will name it, because `raw_market` and `line` now
  travel with every archived quote, and the refusal counters land in
  `localdata/source_health_<day>.json` (`coherence_excluded_rows`,
  `coherence_withheld_fixtures`, `coherence_reason_counts`).
